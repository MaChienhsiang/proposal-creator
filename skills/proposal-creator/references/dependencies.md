# 依赖路由

## 如何调用

在可用技能目录中按名称定位，使用宿主支持的技能调用方式；若无专用 Skill 工具，直接读取对应 `SKILL.md` 并遵循其引用与流程。不要发明工具或认为写出 `$skill-name` 就等于执行。

常见查找位置为同级技能目录、用户指定路径、宿主提供的技能目录及 `${CODEX_HOME}/skills`；也可检查宿主配置的 `.agents/skills`。本套件默认与依赖同处一个技能根目录，但不硬编码用户名或版本路径。

每次只加载当前角色和当前工作所需部分；同一任务已读且未变化的不反复加载。依赖缺失时报告名称及受影响步骤，继续独立工作；不要悄悄降级为“已调用”，也不自动安装。

原始 skill 中的相对资源路径以该原始 skill 目录解析。例如评审文件是 `nsfc-write/references/review-criteria.md`，不是本套件自己的 references/review-criteria.md；domain-modeling 的格式文件也从其原目录读取。

## 跨学科与跨资助类型适配

- nsfc-write：NSFC 项目也以实际当年通知/模板为准。其他项目只借鉴问题—依据—方法—基础的论证方法，不套专属标题、页数、项目定位、任务数量或“避免纯应用开发”等建议；工程研发按其真实目标论证。
- nsfc-policy：是有条件调用，不是所有项目的前置条件。不属于 NSFC 时核对应机构的原始材料；机构未明确时保留待核，不猜政策。
- nsfc-literature：复用检索和引用工具，按学科对象与方法选检索范围；不固定30篇、近5年、国内外比例、CNS优先或数字编号格式。经典理论、专业会议、标准等按其对论断的实际支持选择，引用样式服从模板。
- nsfc-figure：复用申请书概念/方案/技术路线的绘制能力，不导入 NSFC 专属版式；理论项目可只画必要的概念关系，未需要图件时不强制生成。
- nature-figure：按真实图件类型选择数据或示意路径，研究方向不决定绘图后端；不套期刊专属要求。

原技能条款与适用申报要求冲突时，遵循项目适配和原始申报要求，记录具体取舍；不能因依赖名含 NSFC 就把项目重新归类。领域证据和专业判断按实际资料核查，不以通用流程代替。

## grill-with-docs 的跨角色适配

其原始入口要求调用 grilling 和 domain-modeling。本套件把这项组合职责分派给 E 与 A：E 追问并记录未决问题，A 澄清术语并记录决定。若用户明确调用该入口，读取它并用这套跨角色流程执行；不重复启动第二轮相同访谈，不修改已安装的原始 skill。

## 指令冲突的具体处理

- auto-pilot 是用户对内部设计/编写的委托：E 的 grilling 问题由 A 在委托范围内回答，记录 delegated。co-write 的结构、正文和修订沿用用户参与规则；代拟先是建议，明确局部委托才产生 delegated 决定。不要把一次代拟或某节自动完成扩张为整个项目全自动。
- anti-defensive-writing 用于真实优势表达；不能删去指标、证据限定、重要缺口和要求交代的风险，也不能把预期写成已有。
- humanizer-zh 保留信息和确定程度。润色后核对范围、状态、否定、比较符号、统计条件与归因。
- nature-figure 只在数据绘制时处理 Python/R 选择；纯审阅、SVG 或 AI 路径不因此停工。未知绘图语言且无已有/保存偏好时，按原 skill 询问一次；若用户明确授权 agent 选择，按其推荐路径选择并保存。
- 真正适用的官方 AI 使用限制由 D 核实并记录，不以静态速查替代原文，也不以 auto-pilot 改变正式规则。
