# Co-write

共同写作覆盖从架构到成稿的全过程。直接使用 `$proposal-creator co-write …`；`co-pilot`、`co-design`、“共同写作”“一起写”“逐节讨论”进入同一模式。

## 进入与恢复

沿用当前指南、资料、决定、正文和术语。把 `mode: co-write`、当前章节或写作单元、用户保留的决定、已委托事项及下一步记录在 plan.md。恢复任务时先读这些状态，不重新访谈已定事项。结构确认、某节通过或用户说“继续”都不自动改为 auto-pilot；“继续”按原共同写作节奏推进下一个单元。

## 共同设计

A 与用户根据项目类型和研究方法共同商讨主线、任务关系、研究目标与评价；有正式考核指标时统筹其分配。无定量指标时使用合适的论证判据。E 使用 grilling 提出真正影响方案的独立问题，提供推荐答案与理由。用户可自行回答、让 A 代拟、授权选择，或暂缓。A 用 domain-modeling 记录明确的术语和重要取舍。

“让 A 帮我回答”只产生供用户审阅的建议；“由 A 决定并采用”才在指定范围内产生 delegated 决定。暂缓问题保留 pending，继续不依赖它的证据整理和起草。

## 逐节共同写作

1. 沿用用户指定单元；未指定时按已定提纲选择一个章节或逻辑完整的小节，说明本轮范围。允许用户一次授权多个章节，不强制每段确认。
2. A 根据已知意图、指标和 B/D 依据起草可直接修改的正文。目标已清楚时直接起草；缺少实质决定时才提问，不把每轮变成重新访谈。
3. 交付本轮草稿，简述采用的论证、必要缺口及需要用户选择的少量事项。默认等待用户反馈后推进下一个未授权写作单元；等待期间可继续 B/D 补证等独立工作。
4. 用户可修改文字、调整论证、接受草稿，或委托 agent 完成本节。A 落实已有反馈与委托；语言整理、引用校对等已授权工作无需逐项再确认。
5. 改动科学主张、指标分配或方法时请 E 按实际变化复核；普通措辞修改无需每次完整评审。E 的意见交 A 修稿；超出局部授权的重大取舍交用户决定。
6. 当前单元处理完成后更新进度，按用户许可推进下一单元。先前批准的批量范围可连续完成；未解决的决定只阻塞依赖部分。

用户只让某节自动完成时，记录该节的 delegated 范围，整体保持 co-write，完成后回到共同写作节奏。只有明确要求整个任务全自动才切换 auto-pilot。沉默、超时、未回答不算接受，不将待审草稿记为 user-confirmed。

## 角色与收口

A 是用户的写作合作者和主稿维护者；B、D 按需提供证据；C 根据已确定的关系或数据绘图；E 保持独立评审。用户参与论证和取舍，agent 承担具体起草、核对与修订。

最终汇总用户已接受或明确委托的内容、E 的复核结果及剩余缺口。共同写作期间可持续交付有状态的工作稿；未经处理的关键决定不能因到达最后一节而自动关闭。
